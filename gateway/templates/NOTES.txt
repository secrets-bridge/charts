The Gateway has no Kubernetes RBAC and no ServiceAccount token. It reads
Argo CD only, through the connectors listed above.

Enrollment happens once, outside the cluster, before this install. The
pod never enrolls. If the identity Secret does not exist yet, the pod
stays in ContainerCreating. See the chart README, section "Enrollment".

Check the rollout:

  kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "secrets-bridge-gateway.fullname" . }}
  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "secrets-bridge-gateway.fullname" . }}

Look for:
  - "identity loaded"     the identity file was read
  - "connectors bound"    the connectors file was accepted
  - a 401 from the control plane: the Gateway stays up and not ready.
    Revoke it in the console, enroll a new one and update the Secret.

A replica turns ready only after the control plane accepted its
heartbeat and catalog and every Argo CD self-check passed. Readiness is
checked inside the pod with:

  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "secrets-bridge-gateway.fullname" . }} -- /usr/local/bin/gateway healthcheck
