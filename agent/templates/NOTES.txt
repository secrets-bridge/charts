  ⚠️  cp.insecureTransport=true — the agent will trust plain
  HTTP / unverified TLS to the CP. NEVER ship this outside local
  dev.

Identity:     Secret "{{ .Values.identity.existingSecret }}", mounted read-only at
              {{ include "secrets-bridge-agent.credentialsDir" . }} (agent_id, agent_secret, private_key)

  The agent only reads this Secret. It writes no file, PVC or Kubernetes
  Secret, and refuses to start if a file is missing, malformed, or readable
  by others. After a key rotation, update the Secret and restart the agent
  (Reloader does it for you when reloader.enabled=true).

Once the pod is up, verify on the CP side:

  GET {{ .Values.cp.endpoint }}/api/v1/agents

The new agent should appear with `status: active` and a recent
`last_seen_at` within ~30s.

If the agent doesn't show up:

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "secrets-bridge-agent.fullname" . }}

Look for:
  - a credentials error at start (a file is missing, malformed or too open:
                                 fix the Secret, see the troubleshooting docs)
  - agent_key_mismatch (409)    (the Secret's private_key is not the key
                                 bound on the CP: rotation not applied, or
                                 the wrong Secret)
  - 401 / rejected              (agent revoked or wrong agent_secret:
                                 enroll again and replace the Secret)
